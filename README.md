# AI 共创官

**从业务痛点出发，把“想用 AI”推进到可讨论的落地方案。**

AI 共创官是一套中文 AI 诊断与共创应用。用户描述实际工作中的场景和问题，系统通过访谈逐步补充流程、数据、系统、验收与治理条件，再生成机会诊断和实施方案。

项目采用 React + TypeScript 前端与 FastAPI 后端，默认调用本机 Ollama。诊断案例、回答和报告版本保存到数据库，报告可在线阅读，也可导出为 Word 或 PDF。

## 产品流程

1. **建立诊断**：描述业务背景、现有流程与主要问题。
2. **基础访谈**：围绕场景进一步补全事实，形成 AI 机会诊断。
3. **深度共创**：结合已有回答动态追问流程、数据、系统边界及验收要求。
4. **形成方案**：生成专属 AI 落地方案，在线查看并下载文档。
5. **持续管理**：在工作台回看案例与报告，保留历史版本或导出备份。

## 功能与体验

### 两阶段诊断

基础诊断关注痛点与机会；深度共创把问题推进到实施条件。回答质量检查和后续提问由独立服务组织，前端负责呈现访谈阶段和当前进度。

### 报告交付

支持在线报告、历史版本以及 Word/PDF 下载。报告结构围绕业务问题、AI 价值和落地安排组织，生成结果仍需结合实际业务人工确认。

### 本地优先

默认模型为 Ollama `qwen3.5:9b`，地址和模型名称可通过配置调整。当前生成链路默认连接本机模型，不依赖把访谈内容交给外部模型接口。

### 案例与备份

工作台集中管理诊断案例，设置页提供运行状态与 JSON 备份。恢复脚本支持先演练、再写入，并对关联关系和数据结构进行校验。覆盖恢复等操作应先阅读脚本说明并保留备份。

## 技术实现

- **前端**：React、TypeScript、Vite、React Router，组织首页、工作台、分阶段访谈、报告与设置页面。
- **后端**：FastAPI、Pydantic 与 SQLAlchemy，负责输入校验、诊断流程与持久化。
- **模型调用**：Ollama 接口单独封装，模型运行状态和生成失败信息供前端展示。
- **报告导出**：独立服务处理报告内容与文档输出。
- **存储**：默认 SQLite，可通过 `DATABASE_URL` 切换 PostgreSQL。
- **交付方式**：开发时前后端分开启动；前端构建后，后端也可托管静态产物。

## 本地启动

准备 Python、Node.js、npm，以及已运行的 Ollama。先安装所需模型：

```sh
ollama pull qwen3.5:9b
```

安装前端依赖：

```sh
cd frontend
npm ci
```

Windows 从项目根目录运行：

```powershell
.\scripts\start-local.ps1
```

脚本负责启动本地 API 与 Web。也可以分别在 `backend/` 运行 `start.bat`，在 `frontend/` 运行 `npm run dev`。

- 前端：http://127.0.0.1:5173
- 后端：http://127.0.0.1:8000
- 健康检查：http://127.0.0.1:8000/api/health

非 Windows 环境可在 `backend/` 创建虚拟环境、安装 `requirements.txt`，再执行 `python -m uvicorn app.main:app --port 8000`。

## 配置与检查

`backend/.env.example` 提供模型、跨域与数据库配置示例。本地数据库、访谈数据和 `.env` 不随仓库提供。

```powershell
.\scriptserify-local.ps1
```

该脚本包含后端测试、前端 lint 和构建；模型真实推理、数据库连通性与正在运行的服务分别通过可选参数检查。详细用法见 [本地开发说明](docs/LOCAL-DEVELOPMENT.md)。

## 当前范围

这份仓库整理的是当前 AI 诊断与共创应用，未带入旧版需求平台、独立语音服务、本地数据库与历史截图。完整账号体系、租户隔离和数据库迁移属于进一步商用时需要完善的部分。

本次上传不启动本地模型、不修改已有诊断数据；源码检查与真实模型、文档导出的端到端验收分别看待。
