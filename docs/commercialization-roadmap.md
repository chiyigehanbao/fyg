# AI 共创官商业化打磨路线

## 当前定位

AI 共创官当前是一个本地优先的 AI 赋能诊断与方案共创工具。核心价值不是简单聊天，而是把用户的真实业务问题转成两阶段访谈、诊断报告和可执行落地方案。

## 第一阶段：可交付单机版

- 保持默认 SQLite 零配置启动，支持通过 `DATABASE_URL` 切换到本机 PostgreSQL。
- 保持 Ollama 本地模型优先，模型不可用时使用引导式兜底报告，保证演示和销售现场不断流。
- 补齐报告导出、案例复制、案例删除、版本历史、失败重试和本地备份。
- 增加端到端冒烟脚本，覆盖创建诊断、保存访谈、生成基础报告、启动深度共创、生成最终方案。

## 第二阶段：商业 SaaS 雏形

- 引入账号、组织、角色权限和租户隔离。
- 用 PostgreSQL 作为正式数据源，增加 Alembic 迁移、索引、审计字段和备份策略。
- 增加项目看板、客户线索、方案模板、交付状态和导出水印。
- 为报告生成增加可配置行业模板、提示词版本、模型调用记录和人工编辑记录。

## 第三阶段：UNI App 多端适配

- 先保留现有 FastAPI 后端，前端抽离 API 层和页面状态模型。
- 使用 UNI App 重建客户端页面：`pages/index`、`pages/start`、`pages/workspace`、`pages/interview`、`pages/report`。
- UI 组件使用跨端基础组件，避免依赖浏览器专属 DOM 行为；打印/PDF、文件下载、登录态按 Web、小程序、APP 分别封装。
- 小程序端通过后端接口访问数据和模型，不在端上直连本地 Ollama；本地私有化版本再提供局域网后端配置。
- 详细适配评估与迁移清单见 `docs/uni-app-readiness.md`。

## 优先级

1. 先把现有 React + FastAPI 版本打磨到可演示、可交付、可本机私有部署。
2. 再把数据层、账号层和报告版本化做扎实。
3. 最后迁移 UNI App 客户端；迁移前不要同时大改业务流和技术栈。
